# Environments

> Native flavor and Dart config are two halves that must agree; a mismatch compiles cleanly and ships a prod-signed app pointed at the wrong backend.

Console and store verification → `release-readiness.md`. Where config values are consumed → `data-layer.md`.

## 2 · Flavors: two halves that must agree

```
NATIVE   flavorizr.yaml ──▶ Gradle product flavors · Xcode schemes · xcconfigs · icons
                            · app names · Firebase config placement
DART     --dart-define=mode=QA ──▶ String.fromEnvironment ──▶ BuildType ──▶ BuildConfig
                            (base URL · logging flag · FirebaseOptions)
```

```yaml
# flavorizr.yaml
flavors:
  qa:
    app:     { name: "<App> QA", icon: "assets/icon/app_icon_qa.png" }
    android: { applicationId: "com.example.app.qa",
               firebase: { config: "config/firebase/android/google-services-qa.json" } }
    ios:     { bundleId: "com.example.app.qa",
               firebase: { config: "config/firebase/ios/GoogleService-Info-qa.plist" } }
```

```dart
const buildType = String.fromEnvironment('mode', defaultValue: 'DEV');

enum BuildType {
  dev('DEV'), qa('QA'), uat('UAT'), prod('PROD');
  const BuildType(this.value);
  final String value;

  // throws rather than defaulting — a silent fallback is how a prod build points at dev
  static BuildType fromValue(String v) =>
      values.firstWhere((t) => t.value == v,
          orElse: () => throw StateError('Unknown environment: $v'));
}
```

One `lib/main.dart`. `--flavor` selects the native half, `--dart-define` selects the Dart
half, and **a mismatch compiles cleanly and ships a prod-signed app talking to QA** — which
is why every build goes through a script rather than someone's shell history.

Regenerating flavorizr overwrites the native files it manages, so custom Gradle lives outside
the autogenerated markers. Adding a flavor touches seven places: the YAML block, two Firebase
config files, generated Firebase options, the `BuildType` enum, a `BuildConfig` factory, a
build script, and CI. Same spelling in all seven.

Secrets arrive from CI environment variables, base64-decoded at build time. Anything inside
the binary is not secret. Never commit a keystore, `signing.properties`, or a live token.

## 3 · Builds

```sh
# Android
flutter build apk       --release --flavor qa   --dart-define=mode=QA
flutter build apk       --release --flavor qa   --dart-define=mode=QA --split-per-abi
flutter build appbundle --release --flavor prod --dart-define=mode=PROD \
  --obfuscate --split-debug-info=build/symbols/prod

# iOS
(cd ios && pod install)          # required after any new build configuration
flutter build ipa --release --flavor prod --dart-define=mode=PROD \
  --export-options-plist=ios/ExportOptions.plist
flutter build ios --release --no-codesign --flavor qa --dart-define=mode=QA   # CI + fastlane
```

Archive `build/symbols/` per release or every obfuscated crash report is unreadable. An
uncommitted Xcode scheme is what produces *unable to find a scheme matching the flavor*; each
new build configuration needs `pod install` and must keep its `Debug-`/`Release-` prefix so
CocoaPods can map it.

Before any release build: flavor and define agree · version and build number above what's on
that track · codegen committed · analyze clean.
